# Мама и малыш — массаж для мам и малышей

> Обновление 2026-10-11: публичный бренд — **«Мама и малыш»**, Instagram [@mama_i_malish_tj](https://www.instagram.com/mama_i_malish_tj/).
> Новый UI и формы разрабатываются в `feature/mama-i-malish-redesign` (draft PR), без изменения production и данных.
> Разделы ниже описывают также историческую архитектуру `massage_v1`; любые упоминания старого WhatsApp, видео или мобильной навигации относятся к предшествующей версии.
> Запись через восстановленную форму `/contact` пишет в существующую `leads` с прежней RLS; живые тестовые записи в production запрещены.
> Цены/условия централизованы в `src/lib/brand.ts`, изменение публичных текстов через существующий админ-редактор `brand.*`.
> CI выполняет `npm ci`, `npm run lint`, `npm test`, `npm run build`, `npm audit --audit-level=moderate`; браузерные сценарии требуют отдельного реального запуска.
> Требуемый новый Vercel проект `mama_i_malish` и домен `mama-i-malish.vercel.app` пока не подтверждены. Не переименовывать существующий `massage_v1` автоматически.

React + TypeScript + Vite, MUI, существующие Tailwind-стили и Framer Motion; Supabase Auth и PostgreSQL.

## Запуск и проверка

Node.js 24. Установите зависимости в этой папке:

```bash
npm ci
npm run dev
npm run lint
npm test
npm run build
npm run preview
npm audit
```

`build` сначала проверяет TypeScript. GitHub Actions повторяет lint, tests, build и audit при push в main.

Inter включён в сборку и загружается с собственного домена; Google Fonts не требуется. Сохранена лицензия `/licenses/inter.txt`. Страницы входа, регистрации, контактов и мобильное меню загружают свой JavaScript по мере использования. Фоновое видео отложено до первой отрисовки, не загружается при reduced motion, Save-Data или 2G и останавливается вне экрана; доступна кнопка паузы.

Сборка создаёт отдельные HTML-файлы с метаданными для публичных страниц и `noindex` для страниц аккаунта. Настройки Vercel обслуживают эти файлы и задают кеширование только версионированным `/assets/`. При смене домена обновите `src/lib/seo.ts`, `public/sitemap.xml` и `public/robots.txt`. Содержимое страниц остаётся React-приложением; это генерация метаданных, а не серверный рендеринг.

Форма контактов проверяет имя, телефон (9–15 цифр), длину текста и получателя процедуры; показывает ошибки возле полей и сохраняет введённые данные при сетевой ошибке. Повторные события submit во время отправки блокируются. Язык и тема продолжают работать при недоступном browser storage. Тесты дополнены проверками этих ограничений, SEO и криптографической генерации паролей администратора.

Если отдельный JavaScript-файл страницы не загрузился, сайт показывает локализованное сообщение и предлагает обновить страницу. Ошибка загрузки мобильного меню оставляет основную страницу доступной; меню можно закрыть с возвратом фокуса на кнопку. После восстановления сети обновление загружает файл заново. Проверка этих сценариев: после `npm run build` и запуска `npm run preview` выполните `python tests/browser/load-recovery.py http://127.0.0.1:4173` (Python Playwright и Chromium должны быть установлены). Проверка имитирует сбой сети на трёх языках и подменяет все запросы Supabase, не изменяя данные.

Узкие экраны проверяются командой `python tests/browser/narrow-layout.py http://127.0.0.1:4173`: семь маршрутов на трёх языках при ширине 320px. Длинная кнопка детского массажа переносит текст в пределах доступной ширины.

## База

Для нового проекта: `supabase/schema.sql`, старые миграции 02–08, затем SQL из `supabase/migrations/` по порядку. Для существующей базы не запускайте schema.sql повторно: он пересоздаёт политики.

Миграции `20260927202606_security_analytics_mobile.sql` и `20260928020348_visitor_analytics_exclude_admin.sql` применены к подключённому Supabase-проекту. Проверки `tests/security.sql` и `tests/visitor-analytics.sql` работают в transaction и делают ROLLBACK, включая тестовые аккаунты. Второй тест проверяет 1008 просмотров, 1006 уникальных браузеров, источники и исключение администраторов.

## Админ-панель

Войдите администратором через `/login`, затем `/admin`. На ПК есть отдельная кнопка «Админ-панель», на телефоне — нижняя кнопка «Меню». Главная админки содержит прямые переходы с объяснениями. Доступ проверяется в базе по роли и is_active, не только в React.

## Что означает статистика

- Общие показатели вычисляет SQL по всем строкам, независимо от лимита REST API.
- Главная админки и страница статистики используют один компонент показателей и один SQL-отчёт. Журнал событий читает тот же фильтр `analytics_visitor_events`.
- Администраторы (в том числе заблокированные), страницы `/admin` и известные браузеры администратора исключены. После входа админа его visitor_id попадает в защищённый список исключений: прошлые события этого браузера скрываются из отчётов, новые не записываются даже после logout. Исходные события не удаляются. На общем устройстве это исключает весь браузер. До первого входа админа в новом браузере отличить его от обычного гостя нельзя.
- Localhost не отправляет аналитику в рабочую базу, чтобы проверки дизайна не увеличивали счётчики.
- Зарегистрированные клиенты — существующие профили с ролью user; не все попытки регистрации и не пожизненный счётчик удалённых аккаунтов.
- Просмотры и события — записанные сообщения браузера после согласия на аналитику. Отказ, блокировщики и ошибки сети уменьшают охват.
- Уникальный браузер определяется случайным visitor_id. Это не доказательство уникального человека. Очистка хранилища и другое устройство дают новый ID.
- «Активных браузеров за 2 мин.» — page_view или heartbeat за последние 2 минуты. Скрытая вкладка не посылает периодический heartbeat. Это приблизительный показатель.
- Переходы из Instagram/WhatsApp определяются по UTM/referrer. Метки подделываемы, они не подтверждают личность. При отсутствии источника выводится «Источник не передан».
- «Пришли из Instagram/WhatsApp» — уникальные браузеры с записанным просмотром из этого источника. Один браузер может попасть в оба источника. Эти показатели не суммируются; общий показатель посетителей удаляет повторы по visitor_id.
- Имя — из аккаунта сайта после входа. Телефон — самостоятельно введённое поле профиля, не подтверждённый номер WhatsApp. Instagram username не определяется из перехода.
- Клик по WhatsApp не равен сообщению, прочтению или записи на массаж.
- Счётчик заявок берётся из таблицы leads. События не используются как доказательство личности.

Размещайте ссылки `https://ВАШ-ДОМЕН/?utm_source=instagram` и `https://ВАШ-ДОМЕН/?utm_source=whatsapp`. Готовые ссылки текущего домена есть в `/admin/analytics`.

## Мобильное меню и движение

Меню телефона: спокойная графитовая/кремовая палитра, крупные строки навигации, запись в WhatsApp, отдельный блок аккаунта и ссылка администратора, переключатели языка и темы. Панель прокручивается на низком экране; кнопки закрытия и основных действий не меньше 44px. Desktop-header сохраняется от 1024px.

Существующий Framer Motion показывает блоки с лёгкой 3D-перспективой. Фотография в разделе «Что такое баночный массаж» поворачивается и смещается по мере прокрутки. Нативная прокрутка не перехватывается. При `prefers-reduced-motion` новые 3D-эффекты отключены.

## Безопасность и ограничения

- RLS включён на всех публичных таблицах. Тестируются анонимное чтение, чужие профили, повышение роли и блокировка админа.
- Trigger задаёт user_id события из auth.uid() и время сервера, ограничивает типы и размер event_data.
- Ограничения по краткоживущему хешу адреса: 120 событий/минуту, 5 заявок/час, 15 проверок кода/15 минут. Это дополнительный барьер от спама, не защита от распределённых ботов. Сеть за общим NAT может разделять лимит. Заголовки IP нужно проверять на доверенной границе инфраструктуры.
- Код сброса блокируется на время проверки строки, число попыток ограничено; требования пароля совпадают с клиентом. После сброса удаляются refresh-сессии и другие выданные коды. Уже выпущенный access JWT может действовать до истечения срока.
- CSP запрещает inline scripts, object и чужие form-action. MUI требует inline styles. Заголовки из vercel.json действуют при деплое на Vercel; для другого хостинга настройте их отдельно.
- Никогда не добавляйте service_role, secret key или access token в VITE_* и Git. Публичный publishable key допустим, безопасность обеспечивается RLS. Неправильный заданный конфиг теперь выдаёт ошибку вместо имитации пустой базы.
- Supabase Advisor всё ещё отмечает публичные SECURITY DEFINER RPC. Они нужны существующему восстановлению пароля и проверке RLS; это не отсутствие авторизации. private.request_limits намеренно закрыта без публичных политик.
- Leaked Password Protection в Supabase пока выключена. Владелец должен включить её в Authentication, если функция доступна на тарифе. CAPTCHA и MFA админа требуют отдельной настройки; они не внедрены этим изменением.
- Это проверка конкретных сценариев и зависимостей, не гарантия невозможности взлома.

## Название при входе Google — действие в Google Cloud

Название сайта в коде уже «Баночный массаж». Название экрана Google меняется в Google Auth Platform → Branding → App name: **Баночный массаж**. Выберите именно OAuth-проект, Client ID которого настроен в Supabase. Заполните реальные homepage/support/privacy ссылки и пройдите запрошенную Google verification. Нельзя заменить это значение одним React-текстом.

Документация: https://supabase.com/docs/guides/auth/social-login/auth-google и https://support.google.com/cloud/answer/15549049

Ни Branding, ни публикация/verification Google в этой работе не подтверждены: управление Chrome было остановлено инструментом, поскольку он не смог определить текущий URL. Платный custom domain не подключался.
